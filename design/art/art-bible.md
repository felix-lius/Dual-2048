## 1. 视觉支柱与风格关键词

### 一句话视觉定位
> **「一块甜甜的糖，两颗一起跳」——明亮、圆润、暖洋洋的卡通糖果风，让双盘同步的压力看起来轻松又愉快。**

### 风格关键词（Style Keywords）
- **圆润（Round）**：所有方块、按钮、遮罩一律大圆角，拒绝尖锐直角；观感像糖果/积木。
- **明亮（Bright）**：高饱和低沉的色块，背景留白充分，画面通透不压抑。
- **温暖（Warm）**：整体以暖奶油、蜜桃、蜜橘、金黄为基底，传递轻松愉快的情绪。
- **轻盈（Light）**：少阴影、少描边、大留白；对比经典 2048 更「轻」，不笨重。
- **双生（Twin）**：左右两盘视觉同构（同一个模具），仅靠**位置**与可选**侧标签**区分，强调「双盘同步」的镜像感（呼应 GDD 支柱 1「双线协同挑战」）。

### 视觉支柱（与 GDD 设计支柱对齐）
| GDD 支柱 | 视觉翻译 |
| --- | --- |
| 双线协同挑战 | 双盘同构镜像、同步动画；HUD 中间共享总分，左右分对称分布 |
| 低门槛、高上限 | 第一眼亲切（糖果感）；高级玩法靠数字层级（128+ 特殊质感）体现深度 |
| 公平可控的辅助 | 冻结遮罩、退役标记用清晰语义色（蓝=锁定、绿=达标），一眼看懂状态 |

**色板设计逻辑（为什么要这么配）：**
- **亮暗阶梯**：2→64 一路「变深变暖」（奶油→麦→橘→红），128→2048 是「金色系内部变深」。相邻两档在**亮度**上都有肉眼可见的差异，灰度化（看黑白照片）也能分出先后，色弱玩家不靠颜色也能排序。
- **深字/白字规则**：亮底（2/4/8/16 与 128–2048 金色系）用深棕字；深底（32/64）用白字。**优先保证对比度**（见 §8），不照搬经典 2048「黄底白字」这种对比不足的旧做法。
- **2048 的特殊待遇**：它是胜利目标（GDD §2.3），必须第一眼被认出来 → 金色辉光 + 星芒角标 + 数字可略放大 6%。
- 实现提示：上述全部可用 Phaser `Graphics.fillRoundedRect` 绘制；辉光可用 `PostFX` 或叠加一层半透明圆角矩形实现（详见 §9 落地顺序）。

## 3. 方块样式规范

> 现状（`src/view.js`）：圆角 = 格宽 25%，无投影无高光，数字字号 = 格宽 42%（≥1000 缩到 78%，≥10000 缩到 62%）。以下规范在现状上「加质感」，不推翻现有绘制方式。

### 3.1 圆角
- **方块圆角：格宽（cellSize）的 25%**（允许区间 22%–28%，保持糖果感；太小显硬、太大显肿）。
- 棋盘外框圆角：**固定 12–16px**（随棋盘缩放取 `min(16, boardPx*0.04)`），比格子更圆一点，形成「托盘」感。
- 按钮圆角：**高度（h）的 30%**，上限 20px（现实现 `min(18, h*0.3)` 可保持）。

### 3.2 投影与高光（新增，建议落地）
| 元素 | 参数 | 通俗解释 |
| --- | --- | --- |
| 方块投影（drop shadow） | 偏移 (0, 3px) 或格宽 3.5%；颜色 `#000000` 透明度 18%；圆角同方块 | 方块「浮」在格子上，也让「有方块/空格」一眼可分 |
| 方块底部唇边（lip） | 底部 2px 条，颜色 = 方块底色加深 15% | 糖果/按钮的立体厚边 |
| 方块顶部高光 | 上边缘 2px 条，颜色 `#FFFFFF` 透明度 35% | 卡通「被光照到」的亮边 |
| 2048 辉光 | 方块外围 6px 金色 `#FFB014` 透明度 40% 光晕 | 王者专属 |

> 实现提示：Phaser `Graphics` 没有现成 shadow API，可用「先画一块偏色圆角矩形当投影层，再画本体」的方式模拟，成本很低。**投影同时服务无障碍**（见 §2.1 说明）。

### 3.3 方块数字
- 基准字号 = **格宽 × 42%**，粗体 800。
- 缩小规则（保持现有逻辑，作为规范固化）：
  - 数值 ≥ 1000 → 字号 × 0.78；
  - 数值 ≥ 10000 → 字号 × 0.62；
  - 2048 特殊：再放大 6%（格宽 × 42% × 1.06，金色辉光加持）。
- 数字垂直居中、水平居中；金色系方块（128+）数字加 0.5px 深色描边或轻微下移 1px，避免在高亮背景下发虚。

### 3.4 动效建议（时长/缓动，详细见 §7）
| 事件 | 效果 | 时长 / 缓动 |
| --- | --- | --- |
| 滑动 | 平移 | 110–120ms / `Quad.easeOut` |
| 合并 | 弹跳放大 | 放大 120% 后弹回，总时长约 100–130ms |
| 新块 | 弹出 | 0→100% 缩放 / `Back.easeOut`，110–120ms |
| 2048 达成 | 辉光脉冲 | 光晕 1.5s 呼吸 2 次（胜利高亮，GDD §4.3） |

## 4. 字体方案（中英双语 · 离线可用）

### 4.1 硬约束
- **无外网依赖**（GDD §10.1）：不能引 Google Fonts / CDN 字体文件。
- 英文首选 `Nunito` / `Quicksand`（圆润卡通，最贴合风格）——但**本机不一定装了**，所以要接系统字体兜底；中文用系统中文字体（`PingFang SC` / `Microsoft YaHei` / `SimHei`）。
- 若评审后希望「任何机器都长一样」，**后续阶段**可把字体文件本地化进 `assets/fonts/`（不在本版范围，标注【后续阶段】）。

### 4.2 完整 font-family 栈（统一写法，工程直接照抄）
```
font-family:
  "Nunito", "Quicksand", "Varela Round", "Comic Sans MS",
  "PingFang SC", "Microsoft YaHei", "SimHei",
  "Segoe UI", system-ui, -apple-system, sans-serif;
```
- 顺序含义：**英文圆润字体优先 → 中文圆润字体 → 系统兜底**。
- 英文文本会命中 Nunito/Quicksand；中文文本浏览器会跳过不支持的拉丁字体，命中 PingFang/YaHei/SimHei。
- 建议在 `index.html` 的 CSS 与 `main.js` 的 Phaser `fontFamily` 统一使用同一字符串（当前 `view.js/ui.js/menu.js/game.js` 里写的是 `"Nunito","Segoe UI",sans-serif`，**缺中文字体回退**，中文会落到默认字体、观感不一致——这是落地时要修的第一处）。

### 4.3 字号层级（HUD / 方块数字 / 按钮 / Toast）
| 层级 | 字号（参考） | 字重 | 说明 |
| --- | --- | --- | --- |
| 菜单主标题 | 64–72px（随屏宽 `min(72, W*0.12)`） | 800 | 游戏名「Double 2048 / 双倍 2048」 |
| 菜单副标题 | 24–28px | 700 | 口号「Dual Challenge · 双盘同步」 |
| HUD 游戏标题 | 22–24px | 800 | 对局内左上/顶部 |
| HUD 分数（左右/总分） | 18–22px | 800 | 数字比文字大一档 |
| HUD 模式标签 | 14–16px | 800 | 小胶囊「硬核/休闲」 |
| 最高分 | 13–14px | 700 | 小字，不抢戏 |
| 方块数字 | 格宽×42%（见 §3.3） | 800 | 随格子等比缩放 |
| 按钮文字 | 20–26px | 800 | 主按钮 24–26，辅助 20 |
| Toast | 20–24px | 800 | 居中，胶囊底 |

## 5. UI 组件规范

> 所有按钮沿用现有 `Button`（圆角矩形 + 文字），配色见 §2.3；本节省略「尺寸比例 / 圆角 / 配色 / 文字 / 交互态」逐条给齐。

### 5.0 通用交互态（按钮）
| 状态 | 表现 |
| --- | --- |
| 常态 | 圆角矩形 + 底边 3px 同色系加深「投影唇边」，文字居中 |
| **按下（pointerdown）** | **不做缩放**（用户已明确去除缩放抖动）；改为：底边阴影压缩到 0.5px + 填充色加深 12–15%（或透明度 0.85）+ 文字 1px 下移，**即时反馈、无抖动**（推荐，见 §7） |
| 松开 | 恢复常态 |
| 禁用 | 置灰 `#C9C9C9` / 字 `#7A7A7A`，不可点 |
| 选中（菜单模式按钮） | 选中项用满饱和色；未选中置灰（现逻辑已如此，配色按 §2.3 替换） |

### 5.1 开始菜单（`src/menu.js`）
- 布局（竖屏优先居中）：标题 18% 高 → 副标题 → 模式按钮 → 开始按钮 → 底部提示；右上角语言按钮。
- **模式按钮**（硬核/休闲）：宽 `min(320, W*0.7)`、高 64px，两按钮间距 18px；硬核=珊瑚橙 `#F26D5B` 白字（选中）→ 未选中灰；休闲=天蓝 `#7EC8E3` 深字（选中）→ 未选中灰。
- **开始游戏**：草绿 `#5FC25A` 白字，高 70px，是菜单最大的 CTA（行动号召），一眼看到「点这里开始」。
- **语言切换按钮**：右上角，56×48px 小按钮，灰米底；文字显示「目标语言」：当前英文→显示「中」，当前中文→显示「EN」（现逻辑已如此，保留）。
- **副标题/提示**：居中，次文字色 `#6B5B3E` / `#9C8F7C`。
- 建议：标题「Double 2048 / 双倍 2048」可加 2–3 颗星芒/糖果点装饰（可选，非必须）。

### 5.2 对局 HUD（`src/game.js` buildHUD）
- 横屏：顶部一条 HUD，高 ≈ `max(72, H*0.11)`：
  - 左上：**最高分**（小字，`Best / 最高分`）；
  - 左上偏中：游戏标题（22px）；
  - 中间：**总分**（大数字，20–22px）；
  - 左 25% 处：**左盘分**；右 75% 处：**右盘分**（左右对称，呼应「双生」）；
  - 顶部中央下沿：**模式标签**（14–16px 小胶囊：「硬核/休闲」）。
- 竖屏：HUD 保持同一套元素，压缩高度，标题可隐藏或缩到 18px，保证棋盘空间优先。

### 5.3 控制条（底部）
- 5 个按钮等距铺开（撤销/冻结/重开/全屏/首页），`slot = W/6`；按钮 120×52px（触屏目标 ≥44px，52 达标）。
- 顺序与配色见 §2.3：撤销（天蓝）、冻结（黄）、重开（珊瑚）、全屏（蓝紫）、首页（薄荷绿）。
- 右上角：**隐私政策**小字（占位链接，GDD §13）。

### 5.4 结算遮罩（`buildOverlay`，胜利/失败/双达标）
| 场景 | 遮罩 | 标题文案 | 按钮 |
| --- | --- | --- | --- |
| 胜利（任一盘 2048） | 深海军蓝 78% 全屏 + 金色光晕顶部 | 白字 40px，可加一行金色小字 | 草绿「再来一局」 |
| 双达标（休闲 `bothDone`） | 同上，标题换「双盘均达标！」 | 金色辉光强调 | 同上 |
| 失败（硬核/休闲） | 同上（无金色光晕） | 白字 40px + 原因小字 | 同上 |

- 出现动画：遮罩淡入 150–200ms；标题随遮罩 0.95→1 轻微放大；按钮晚 80ms 出现（详见 §7）。
- 按钮尺寸 200×60px，圆角 30%h。

### 5.5 冻结遮罩（`view.js` showFreeze）
- 被冻结盘：整盘盖深海军蓝 `#1D3557` 55% 半透明圆角遮罩。
- 中央内容：**锁形图标**（建议用 Graphics 画一把小锁，或用简单几何图形代替）+ **「冻结中」** + **剩余步数**（大号白字 800）。
- 出现动画：淡入 150ms + 内容轻微弹跳；步数每 -1 时数字脉冲一次（缩放 1.15→1，100ms）。
- 与 GDD §4.3 一致：遮罩 + 锁形图标 + 剩余计时。

### 5.6 退役「DONE」标记（`view.js` showRetired，休闲达标盘）
- 整盘盖青绿 `#2A9D8F` 60% 半透明圆角遮罩。
- 中央：白字「DONE 达标」（英文 DONE + 中文 达标 并排，主英文 30px 800）。
- 出现动画：淡入 + 轻微 pop（0.9→1，120ms）。
- 语义：这盘「功成身退」继续玩另一盘（GDD §6.3 退役）。

### 5.7 Toast（`ui.js` showToast）
- 胶囊形：圆角 = 高度一半；内边距 14×8px；居中偏上（y ≈ `max(60, H*0.1)`）。
- 底色 `#FFF3C4`、字 `#5C4700`；成功变体薄荷绿白字；警示变体珊瑚橙白字（见 §2.3）。
- 生命周期：停留 700ms → 1300ms 内淡出并上移 26px；深度 1000（最顶层）。

## 6. 布局与响应式

> 现状（`game.js` layout）：横屏并排、竖屏堆叠已实现。以下给「视觉节奏」层面的规范，数值沿用工程已调好的参数，避免推倒重来。

### 6.1 横屏（优先）
- 双盘左右并排，两盘间距 `min(40, W*0.04)`。
- 顶部 HUD（≈11% 高）→ 中部双盘（占满剩余）→ 底部控制条（≈13% 高）。
- 视觉节奏：**两侧留白 12px**；双盘以画面中线左右对称；共享总分居中，形成「左盘 — 总分 — 右盘」的阅读顺序。

### 6.2 竖屏（堆叠）
- 双盘上下堆叠，盘间距 `min(24, H*0.025)`。
- HUD 在顶部、控制条在底部，棋盘区占满中间；竖屏下标题可缩小（见 §5.2）。

### 6.3 棋盘内部比例（工程已定，固化为规范）
- **方块间距 gap ≈ 格宽的 5%**（格内留白小，棋盘显得紧凑饱满）。
- **外框内边距 ≈ 棋盘尺寸的 3%**（居中后自然得到）。
- 棋盘最大不超过可用区域 96%，保证双盘始终同屏。

### 6.4 安全区（内嵌网页）
- 关键可点元素（按钮、语言切换、隐私政策）距屏边 **≥ 10px**（现实现 12px，达标）。
- 顶部 HUD 内容避让刘海/状态栏：默认从 y=12 起排（现实现如此）。
- 记住 可能叠加自家 UI/横幅，底部控制条不要贴死 0px，预留 ≥8px 呼吸空间。

## 7. 动画规范

> 双盘**必须同帧同步、起点与时长一致**（GDD §2.2/§4.4 硬约束）——动画参数以「一次输入」为单位同时作用于两盘。

| 动画 | 效果 | 时长 | 缓动 | 备注 |
| --- | --- | --- | --- | --- |
| 方块滑动 | 从旧格平移到新格 | 110–120ms | `Quad.easeOut` | 先快后慢，手感轻快；现 110ms 可保留 |
| 合并弹跳 | 目标块放大 120% 再弹回 | 放大 60ms（延迟 45ms 后）+ 回弹 60ms | `Quad.easeOut` | 现逻辑 1.18 → 规范统一 1.20 |
| 新块弹出 | 0→100% 缩放出现 | 110–120ms | `Back.easeOut` | 有轻微「过头再回」的弹性，是糖果感来源 |
| 撤销回退 | 双盘快照瞬间还原 + 轻微整体闪一下（白色 10% 覆盖 60ms） | 短促 ≤100ms | — | GDD §4.3「短促回退动画」 |
| 冻结遮罩出现 | 淡入 + 内容 0.9→1 | 150ms | `Quad.easeOut` | 消失：淡出 120ms |
| 退役 DONE | 淡入 + 内容 pop | 120ms | `Back.easeOut` | — |
| 结算遮罩 | 全屏淡入，标题 0.95→1 | 150–200ms | `Quad.easeOut` | 按钮晚 80ms 弹出 |
| 2048 辉光 | 光晕呼吸 2 次 | 1.5s 总 | 正弦 | 胜利高亮（GDD §4.3） |
| **按钮按下反馈** | **无缩放**：阴影压缩 3px→0.5px + 填充色加深 12–15% + 文字下移 1px | 即时（<50ms） | — | **替代原来的缩放抖动**，用户已确认去除缩放；用「压下去」的立体感代替 |

**为什么按下不缩放、改「压下去」**：缩放（哪怕 0.95）在快速连点时会显得抖动、廉价；「阴影压缩 + 颜色加深 + 文字下沉」是物理按钮的「按下去」逻辑，反馈更扎实，且不改变可点区域大小（不影响误触判定）。**这是主推方案，待用户确认。**

## 8. 无障碍（可访问性）

> 对齐 GDD §12（【待实现】）与 对外交付友好；本文档给美术侧可落地的规格。

### 8.1 色盲友好：数字 + 图案双重标识（不只靠颜色）
- **数字是首要标识**：方块值永远是数字，颜色只是辅助——这是 2048 天生的优势，继续强化。
- **高数值图案角标（建议新增，可选）**：给 128/256/512/1024/2048 各加一个**右上角小星芒/圆点**角标（128=1 个点，256=2 个点，512=3 个点，1024=星芒，2048=皇冠/星芒+辉光）。这样色弱/色盲玩家不看颜色也能凭角标数量知道「这盘已经到黄金段位」。
- **灰度可读性**：§2.1 色板已保证相邻数值在灰度下亮度不同；落地后建议用「灰度滤镜」截图复核一遍。
- 冻结/退役/胜利不只靠颜色：**冻结遮罩带锁形+步数文字**、**退役带「DONE 达标」文字**、**结算遮罩带大字文案**——颜色变化永远伴随文字/图标变化。

### 8.2 对比度要求
- **方块数字**（大字号粗体，视为「大文字」）：目标 **≥ 3:1**，能做到 4.5:1 更好。本版色板：深字组（2/4/8/16 与金色系）对比度均 ≥ 4.5:1；白字组（32/64）约 3:1 上下——**落地时用对比度检查器复核一次**，若 32 差一点，就把 32 再加深 5%（如 `#F75C40` → `#F04F30`）。
- **正文/按钮文字**：目标 **≥ 4.5:1**；小字（最高分/隐私）≥ 4.5:1。
- 按钮深字 `#1F3A4D` 在天蓝/薄荷绿/灰米底上均 ≥ 4.5:1（可复核）。

### 8.3 字号可放大
- 关键数字（方块数字、分数）随棋盘/屏幕等比缩放，天然可放大。
- 设置项预留「大字号」开关（【待实现】，与 GDD §12 对齐）：开启后 HUD/按钮字号 ×1.25。

### 8.4 减少动画选项（【待实现】）
- 设置项「减少动画」（GDD §4.4/§12）：开启后——
  - 滑动/合并/新块：改为**瞬移**（无过渡）；
  - 遮罩：仅淡入（无弹跳）；
  - 辉光/脉冲：全部关闭；
  - 按钮反馈保留「颜色加深」（它不属于运动动画，不影响眩晕）。
- 实现建议：把所有动画时长集中到一个参数表，开关直接置 0 或走 `tweens.disable`。

### 8.5 输入替代
- 键盘方向键 + 触屏滑动双通道（已实现，GDD §10.4），保持。

### 9.1 当前资产形态（重要）
- **本项目目前是「零图片资源」**：方块、按钮、遮罩全部用 Phaser `Graphics` 代码绘制（`src/view.js` / `src/ui.js`）。这是**优点**：体积小、加载快、随代码缩放清晰（适合无外网依赖 + 内嵌）。
- **本文档推荐继续用代码绘制**，不做图片替换。以下 9.2 的图片规格是「将来若要做更丰富质感（贴图纹理/渐变/装饰）」的备选方案，**不阻塞当前落地**。

### 9.3 落地优先级（给工程的分步实施顺序）
> 每步独立可验收，做完一步视觉就上一个台阶，不影响功能。
1. **色板替换**（最快见效）：把 `view.js` 的 `COLORS` 表、`menu.js`/`game.js` 的背景色、`ui.js` 按钮默认色，替换成 §2 色板。→ 验收：画面整体变「正式」。
2. **背景渐变 + 棋盘底色**：加一张全屏渐变铺底（方案 A 或 B，待拍板）；棋盘外框/空格换成 §2.2 色。→ 验收：背景有层次。
3. **方块质感**：加投影、底部唇边、顶部高光（§3.2）；2048 辉光。→ 验收：方块「浮起来」。
4. **字体栈统一**：`index.html` CSS + `main.js` 与各场景 `fontFamily` 统一为 §4.2 栈（**补上中文字体回退**）。→ 验收：中文观感一致。
5. **UI 组件**：按钮配色按 §2.3、按下反馈改「阴影压缩+加深」、toast 变体色、冻结/退役/结算遮罩色与文案。→ 验收：交互有质感、无缩放抖动。
6. **动画参数化**：把时长/缓动集中为一个参数表（§7），挂「减少动画」开关（§8.4）。→ 验收：开/关动画都有手感。
7. **无障碍复核**：灰度截图检查相邻方块、对比度检查器复核深/白字、高数值角标（§8）。→ 验收：色弱玩家可玩。

### 9.4 命名规范（代码侧建议）
- 颜色统一用语义名：`COLOR_TILE_2`、`COLOR_TILE_2048`、`COLOR_BG_TOP`、`COLOR_BG_BOTTOM`、`COLOR_FREEZE_OVERLAY`、`COLOR_RETIRED_OVERLAY`、`COLOR_TOAST_BG`…集中放一个常量文件（如 `src/theme.js`），避免散落魔法数。

## 0. 文档约定

### 0.1 设计支柱（Design Pillars）
为防止「支柱漂移」，全文设计决策统一对齐以下三条支柱：
1. **双线协同挑战**——核心动词是「一次滑动，双盘同步」，玩法张力来自双盘的并行推进与资源权衡。
2. **低门槛、高上限**——滑动即玩、一局短平快；硬核模式与辅助资源管理提供深度。
3. **公平可控的辅助**——撤销 / 冻结是「缓压工具」而非「碾压手段」，因此限次、防刷、不可无限滚雪球。

## 1. 游戏概述

### 1.1 游戏概念（Concept）
《双倍 2048：双重挑战》是在**单一窗口内并排两个独立 4×4 棋盘**的 2048 变体。玩家用一次方向键 / 触屏滑动**同时驱动两个棋盘做相同的滑动与合并**；两个棋盘各自独立生成新块、独立计分。游戏考验玩家在「双线并行」下的规划与辅助资源（撤销 / 冻结）管理。

一句话定位：**一次滑动，双盘同步；在双重压力中冲上 2048。**

### 1.2 核心特色（Features）
- **双盘同步**：一次输入，双盘并行结算、同步播动画。
- **双模式**：硬核「任一盘死局即负」/ 休闲「双盘皆死才负」，开始菜单切换。
- **两支辅助**：撤销（Undo，回退一步）、冻结（Freeze，锁定一盘争取发育空间）。
- **卡通圆润视觉**：明快、低门槛的美术基调。
- **跨端 H5**：横屏并排、竖屏上下堆叠，适配桌面与移动端内嵌视图。

### 1.3 目标用户
- 休闲益智玩家、2048 老玩家、移动端碎片化时间用户。
- 年龄段约 10–45 岁；强调「上手零门槛、精通有深度」。

### 1.4 平台与发布
- 首发平台：**平台**（网页 + APP 内嵌 iframe）。
- 形态：HTML5，纯前端、无外网依赖（见 §10）。
- 屏幕：横屏优先；竖屏自动上下堆叠（见 §4.1）。

### 1.5 技术引擎
- **Phaser 3（原型 3.80.1）**，已本地化到 `vendor/phaser.min.js`，**无任何外网 / CDN 依赖**（见 §10.1）。

## 2. 核心玩法

### 2.1 基础规则
- 每个棋盘为 4×4 网格，初始各自生成 2 个新块。
- 玩家输入一个方向（上 / 下 / 左 / 右），该方向**同时**作用于两个棋盘：
  - 棋盘内所有方块沿该方向滑动，相邻相同数字合并为双倍值。
  - 合并规则与经典 2048 一致（一次滑动中，一个块最多合并一次）。
- 滑动后，发生移动的棋盘独立生成一个新块（见 §2.2、§6.1）。
- 每个棋盘独立计分；**总分 = 左盘得分 + 右盘得分**。

### 2.2 双盘同步机制（关键）
- **同帧并行结算**：输入事件触发后，两个棋盘在**同一帧内并行计算**滑动 / 合并结果。
- **同步动画**：双盘动画**起点一致、时长一致**，同时播放（不得一盘先动一盘后动）。
- **新块 / 计分对齐**：**只有在本回合发生「有效移动」的棋盘，才生成新块并计分**；未发生移动的棋盘（例如因被冻结而锁定，或该方向上本就无变化）不生成新块、不计分。
- 该规则保证死局判定、胜负判定与「有效移动」口径完全对齐（见 §2.3、§6.3）。

### 2.3 胜负判定
- **胜利目标**：任一棋盘达到 **2048** 即触发胜利状态（玩家可选择继续「无尽模式」或结束）。
- **失败（硬核模式，默认）**：**任一非冻结棋盘进入死局**（四个方向均无法移动 / 合并）即判负。
- **失败（休闲模式）**：**所有非冻结棋盘皆进入死局**才判负（单盘死局可继续）。
- **胜负优先级：先胜后负**。每回合先判定是否有棋盘达标（胜），再判定死局（负）；若同一回合同时出现「达标」与「死局」，以**胜利**为准。
- **冻结与胜负无关**：胜负判定只看是否达标 / 死局，与某盘是否处于冻结状态无关（见 §6.3）。
- **模式切换**：开始菜单提供硬核 / 休闲切换；切换立即生效于下一局（当局进行中不可切换，避免状态歧义）。

### 2.4 「有效操作 / 有效移动」统一定义（全文档唯一口径）
> **玩家按一次方向键（或一次有效滑动手势）后，若至少一个棋盘发生了「移动」或「合并」（即棋盘状态改变），则该次输入记为一次「有效操作 / 有效移动」（valid global move）。**

- 若两个棋盘在该方向上都无任何变化，则**不是**有效移动（不计入冻结计时、不生成新块、不消耗资源、不计步）。
- 此定义统一适用于：冻结计步（§3.2）、撤销判定（§3.1）、新块 / 计分对齐（§2.2）、死局判定（§2.3）。

### 2.5 得分规则
- 每次合并产生分数，分值为**合并后新块的面值**（例如两个 2 合并成 4，得 4 分；两个 1024 合并成 2048，得 2048 分）。
- 双盘独立累计，HUD 分别展示左 / 右盘分与总分。
- 总分用于：最高分记录（§3.3）、冻结得分奖励阈值（§3.2）。

## 3. 系统详细设计

### 3.1 撤销系统（Undo）
- **免费额度**：每局 **5 次**免费撤销。
- **撤销行为**：恢复「最近一次有效全局移动」前的双盘棋子布局与计分快照（回退一步）。
- **耗尽后的激励视频续次**：
  1. 免费 5 次用尽后，再次点击撤销 → 弹出**激励视频**入口。
  2. 玩家看完激励视频 → 获得 **5 次临时撤销**。
  3. 临时撤销**仅当局有效、不跨局累积、当局内无获取上限**（可反复看广告续次）。
- **防刷约束**：
  - 撤销**不影响**撤销次数本身、冻结次数、冻结锁定状态与计时（元资源不随撤销回滚）。
  - 冻结得分奖励（§3.2）**不随撤销回滚**（明确防刷设计，见 §16 已知限制）。
- **边界**：对局未开始 / 已结束不可撤销；已无历史快照时撤销按钮置灰。

### 3.2 冻结系统（Freeze）
- **激活次数**：每局 **3 次**冻结激活。
- **激活行为**：点击冻结 → 选择锁定**左盘**或**右盘**；被锁定盘在冻结期间：
  - 不响应滑动（不移动 / 不合并）；
  - 不生成新块、不计分（与 §2.2 对齐）。
- **冻结计时（时长计量）**：
  - 以「有效全局移动」为单位倒计时。
  - 每发生一次**有效全局移动**（见 §2.4），当前冻结计时 **-1**。
  - 计时归 **0** 时**自动解除**锁定（不是「每次按方向键都减」——无效滑动不消耗计时）。
  - **初始时长值（FREEZE_DURATION_MOVES）待主理人拍板**：草稿曾出现「5 次有效移动」表述，本版建议默认 **3 次有效移动**（保护性但不超模）；具体数值以 §16 待办确认为准。该值为可调参数，不在代码中硬编码魔法数。
- **得分奖励（额外激活次数）**：
  - 双盘**总得分**每增加 **1000 分**，冻结激活次数 **+1**（仅当局有效、无上限）。
  - 触发时 UI 给出明确提示（气泡 / Toast）。
- **约束**：
  - **冻结中不可再次冻结**（须等当前冻结解除，或该局冻结已用尽）。
  - 得分奖励不随撤销回滚（防刷，见 §3.1）。

### 3.3 分数与记录
- **当前分**：本局双盘总分，HUD 实时展示。
- **最高分**：
  - 首版为**本地最高分**（`localStorage` 持久化，见 §10.3）。
  - **跨平台排行榜需后端，列为后续阶段**（见 §14），首版不实现。
- **记录范围**：仅持久化「最高分」与「设置项」；**当前对局状态不持久化**（刷新即新局）。

## 4. 界面与美术

### 4.1 布局
- **横屏**：左右并排双盘，中间为共享 HUD（总分 / 最高分 / 模式 / 撤销与冻结次数）。
- **竖屏**：自动切换为上下堆叠双盘，HUD 置于顶部或底部。
- **响应式**：基于视口尺寸自适应缩放，保持双盘等比、可点区域充足（适配触屏）。

### 4.2 卡通视觉规范
- 基调：圆润边角、明快配色、块面数字、轻量描边。
- **原型现状**：当前卡通视觉为**占位美术**（见 §16）。
- **正式美术圣约（Art Bible）由美术负责人后续产出**，本文档不定义最终色板 / 字号细节。
- 数字块配色需预留**色盲友好**对照方案（见 §12）。

### 4.3 状态反馈
- 合并：缩放 / 高亮脉冲。
- 新块生成：淡入 / 弹出。
- 冻结：被锁定盘叠加半透明遮罩 + 锁形图标 + 剩余计时。
- 撤销：短促回退动画 + 轻微反馈音（音效为【后续阶段】）。
- 达标 2048：胜利横幅 / 高亮。
- 死局：失败遮罩 + 重开入口。

### 4.4 动画
- 双盘动画**同帧同步、起点与时长一致**（见 §2.2）。
- **减动画开关【待实现】**：开启后简化 / 跳过过渡动画（无障碍，见 §12）。

## 5. 辅助交互流程

### 5.1 输入 → 结算主循环
```
玩家输入方向（键/滑动）
   │
   ├─ 并行计算左盘、右盘滑动/合并结果（同帧）
   │
   ├─ 判定「有效全局移动」（至少一盘状态改变？）
   │      ├─ 否 → 忽略（不计时、不生成、不计分）
   │      └─ 是 → 播放同步动画
   │             ├─ 发生移动的盘：生成新块 + 计分
   │             ├─ 冻结计时 -1（若处于冻结）
   │             └─ 触发得分奖励判定（每+1000分 +1冻结）
   │
   └─ 胜负判定（先胜后负）→ 达标/死局处理
```

### 5.2 撤销流程
```
点击撤销
   ├─ 免费次数 > 0 → 消耗 1 次，回退一步
   └─ 免费次数 = 0 → 弹激励视频
                      ├─ 看完 → +5 临时撤销 → 回退一步
                      └─ 关闭/未看完 → 不发放，保持原态
```

### 5.3 冻结流程
```
点击冻结（且当前未冻结、且本局仍有激活次数）
   ├─ 选择 左盘 / 右盘
   ├─ 锁定该盘，启动计时（FREEZE_DURATION_MOVES）
   ├─ 每次有效全局移动 计时 -1
   └─ 计时=0 → 自动解除
得分每 +1000 → 冻结激活次数 +1（有提示）
```

## 6. 难度与平衡

### 6.1 新块生成概率
- 每个棋盘**独立**生成新块，各自判定：
  - **约 90% 概率出 2**，**约 10% 概率出 4**（数值为建议默认值，可作平衡微调参数）。
- 仅在「发生有效移动的盘」上生成（见 §2.2）。
- 单回合最多每盘各生成 1 个新块。

### 6.2 难度曲线
- 随盘面被填满，可合并空间下降，死局概率上升（与经典 2048 一致）。
- **双盘叠加效应**：硬核模式下任一盘死局即负，使实际难度高于单盘 2048；休闲模式显著降低挫败感。
- 辅助资源（撤销 / 冻结）提供「缓压」而非「通关」——限次 + 防刷保证不出现主导策略（design pillar 3）。

### 6.3 边界情况规则
| 场景 | 判定 |
| --- | --- |
| 同回合双盘**同死局** | 硬核：负；休闲：负（一致） |
| 同回合双盘**同达 2048** | **胜利**（先胜后负） |
| 同回合一盘达标、一盘死局 | **胜利优先**（先胜后负） |
| 冻结中的盘先达 2048 | **算赢**（胜负与是否冻结无关） |
| 仅一盘死局（另一盘存活） | 硬核：负；休闲：继续 |
| 被冻结盘「死局」 | 冻结盘视为暂停、**不参与死局判定**；以非冻结盘状态为准 |
| 有效移动但某盘无变化 | 该盘不生成新块 / 不计分（§2.2） |
| 输入无效（双盘均无变化） | 不计为有效移动，不计时、不生成、不消耗资源 |

## 10. 技术规范

### 10.1 Phaser 3 本地化
- 使用 `vendor/phaser.min.js`（3.80.1），**无 CDN / 外网请求**。
- 所有资源（JS / 美术 / 字体）随包发布，符合 内嵌 iframe 离线运行要求。

### 10.2 性能预算
- 双盘同帧并行结算 + 同步动画，目标 **≥ 30 fps**（低端机可降级动画复杂度 / 简化过渡）。
- 建议：合并计算与渲染分离；避免每帧全量重绘；对象池复用块精灵。

### 10.3 持久化
- `localStorage` 持久化：最高分、设置项（模式、静音、减动画、引导跳过）。
- **不对局状态持久化**（刷新即新局）。

### 10.4 适配
- 横屏并排 / 竖屏堆叠的响应式布局（见 §4.1）。
- 触屏滑动手势 + 键盘方向键双输入（见 `src/input.js`）。

### 10.5 无外网依赖
- 全包自包含，符合发布与离线运行要求（见 §13）。

### 17.2 术语表
| 术语 | 含义 |
| --- | --- |
| 双盘同步 | 一次输入同时驱动左右两盘并行结算与动画 |
| 有效移动（valid global move） | 一次输入后至少一盘发生移动 / 合并（§2.4） |
| 死局 | 某盘四个方向均无法移动 / 合并 |
| 硬核模式 | 任一非冻结盘死局即负（默认） |
| 休闲模式 | 所有非冻结盘皆死局才负 |
| 冻结计时 | 以有效全局移动为单位的冻结剩余时长 |
| 临时撤销 | 看广告获得的、仅当局有效的撤销次数 |
| 防刷 | 限制资源滚雪球（冻结奖励不回滚、临时撤销不累积） |
| 圣约 / Art Bible | 美术风格规范文档（后续由美术负责人产出） |

### 17.3 关键参数速查
| 参数 | 值 | 备注 |
| --- | --- | --- |
| 棋盘 | 4×4 × 2 | 左右独立 |
| 免费撤销 | 5 / 局 | 耗尽看广告续 |
| 临时撤销 | +5 / 次看广告 | 仅当局、无上限 |
| 冻结激活 | 3 / 局 | 得分每 +1000 再 +1 |
| 冻结时长 | FREEZE_DURATION_MOVES（待拍板，建议 3） | 有效移动倒计时 |
| 新块概率 | 2 约 90% / 4 约 10% | 每盘独立 |
| 胜利目标 | 任一盘达 2048 | 可继续无尽 |
| 性能目标 | ≥ 30 fps | 低端机降级 |
| 最高分 | 本地（localStorage） | 跨平台榜后续 |

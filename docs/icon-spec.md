## 1. 图标要解决的问题（v1.0 原始内容，保留参考）

平台列表页里，图标是**唯一**的第一触点：它和几十个同类小游戏并排出现，尺寸常被缩到 **80–120px**。所以图标不是"缩小版游戏画面"，而是一个**远看能认出、近看有质感**的标志。

三个必须在 1 秒内传达的信息：

| 优先级 | 要传达 | 视觉手段 |
| --- | --- | --- |
| 1 | 这是 **2048 类**数字合成游戏 | 经典圆角方块 + 大号数字 |
| 2 | 这是 **"双"** 的变体（差异化卖点） | **两块**方块并置/叠置，构成"一对"的意象 |
| 3 | 这是**轻松暖色卡通**风，不是冷硬极简风 | 橙黄暖色 + 大圆角 + 高光唇边 |

> 差异化提醒：市面 2048 图标绝大多数是**冷灰/米白底 + 单个方块**。我们用**暖橙 + 双块**，在列表里天然跳出来。

## 2. 构图思路（最终采用方案）

### 2.1 主方案：双块叠置（Twin Tiles）

```
        ┌──────────────────┐
        │   ✦              │   ← 金色星芒点缀（#FFB014）
        │      ┌─────┐     │
        │      │  2  │     │   ← 后块：蜜橘 #FFC97B，深棕字
        │   ┌──┴──┐  │     │
        │   │  4  │──┘     │   ← 前块：橘橙 #FFA95E，深棕字
        │   └─────┘     ✦  │
        │                  │
        └──────────────────┘
          暖奶油→蜜桃渐变底
```

- **两块方块斜向叠置**（像一对骰子），前块压住后块一角 → 一眼看出"**两个**盘"，而不是一个。
- 数字选 **2 和 4**：2048 系列最本源的两个数，认知成本为零；且 2→4 本身就是"合成"的暗示。
- **不用 "2048" 四位字样**做主体：四个字符在 100px 缩略图下会糊成一条横线，可读性差。数字 2 / 4 单字符最抗缩放。
- **斜向 8°–12° 微倾**：打破正方形的呆板，增加卡通俏皮感；但不超过 12°，否则小尺寸下像"歪了"。

### 2.2 备选方案（若主理人/用户想换）

| 方案 | 描述 | 优点 | 风险 |
| --- | --- | --- | --- |
| B · 左右并排双块 | 2 和 4 严格左右并排，正对观众 | 最直白的"双盘"表达，对称稳重 | 略平淡，缺少纵深 |
| C · "2048" 艺术字 + 双格轮廓 | 大字 2048，下方两个小方框轮廓 | 品牌名直给 | 小尺寸下 4 个字符糊掉，**不推荐** |
| D · 单块 2048 王者金 | 一块金色 2048 方块 + 辉光 | 最"高级" | 丢失"双"的差异化，泯然众人 |

> **主推 A。** B 可作为 A/B 测试的第二版素材。

## 3. 色彩规格（严格取自美术圣经 §2）

| 元素 | 色值 | 来源 |
| --- | --- | --- |
| 背景渐变 · 顶部 | `#FFF9EF` 暖奶油白 | 美术圣经 §2.2（方案 A，已在 `theme.js` 落地） |
| 背景渐变 · 底部 | `#FFE6D2` 蜜桃粉 | 同上 |
| 后块（数字 2） | 底 `#FFC97B` / 字 `#4A2A0E` | 美术圣经 §2.1 「8」档蜜橘 |
| 前块（数字 4） | 底 `#FFA95E` / 字 `#4A2A0E` | 美术圣经 §2.1 「16」档橘橙 |
| 星芒点缀 | `#FFB014` 王者金 | 美术圣经 §2.1 「2048」档 |
| 顶部高光 | `#FFFFFF` @ 35% | 美术圣经 §3.2 |
| 底部唇边 | 本体色加深 15% | 美术圣经 §3.2 |

> **为什么方块不用 2/4 档的原色**（`#FFF6E3` / `#FFEBC8`）：那两档是奶油白与麦穗黄，**在奶油白背景上几乎看不见**。图标语境下优先保证「方块从背景里跳出来」，所以借用了 8/16 档的蜜橘与橘橙，同时保留「浅→深」的层级关系（2 比 4 浅一档），色彩逻辑仍与棋盘一致。这是**有意的偏离**，已按美术圣经要求在此标注。

## 4. 形状与技术规格

### 4.1 尺寸与格式

| 规格项 | 要求 |
| --- | --- |
| 主尺寸 | **512×512 px**（平台要求） |
| 格式 | **PNG-24**（支持 alpha） |
| 色彩空间 | sRGB |
| 文件体积 | 建议 ≤ 200KB（可用 TinyPNG / `oxipng` 压） |
| 文件名 | `assets/icon-512.png` |
| 派生尺寸（备用） | 256×256 / 128×128 / 64×64，从 512 等比降采样 |

### 4.2 圆角与透明底

- **画布本身保持正方形、四角内容满铺**（不预裁圆角）。
  > 理由：平台与多数平台会**自行套用圆角遮罩**。如果我们自己先裁了圆角、再被平台裁一次，会出现"双重圆角"的白边缺口。**交付满铺方图最安全。**
- 若某处需要**自带圆角**的版本，圆角半径取 **512 × 22% ≈ 112px**（与美术圣经 §3.1 方块圆角 22–28% 区间对齐），另存为 `icon-512-rounded.png`，不覆盖主文件。
- **透明底**：主文件采用**不透明暖色渐变底**。
  > 理由：图标在平台深色/浅色卡片上都要显示，透明底会导致方块"漂浮"在不可控的底色上，暖色调直接丢失。暖奶油底本身就是品牌资产的一部分，必须保留。若平台明确要求透明，另出 `icon-512-alpha.png`（仅双块 + 星芒，无底）。

### 4.3 安全区（Safe Area）

```
512 × 512 画布
├─ 外圈 48px：出血区 —— 只放背景渐变，不放任何关键内容
└─ 内圈 416×416：主体安全区 —— 双块与数字必须完全落在此区内
```

- 平台圆角遮罩最多吃掉角上约 40–50px，48px 出血可保证**数字永不被切**。
- 双块整体视觉重心**略高于几何中心 2%**（约 10px），因为人眼在方形里会觉得正中心偏低。

## 5. 必须避免的元素（Do NOT）

| ✗ 禁止 | 原因 |
| --- | --- |
| 写实照片、渐变网格、复杂纹理 | 与 warm cartoon 风格冲突，小尺寸糊成一团 |
| 细描边（< 3px）、细线装饰 | 缩到 100px 后消失或产生摩尔纹 |
| 超过 2 个数字字符 | "2048" 四字在缩略图下不可读（见 §2.2 方案 C） |
| 附加文案（"HOT" / "NEW" / "FREE" / 中文标语） | 平台明令禁止促销角标；也挤占安全区 |
| 平台 Logo、任何第三方商标 | 侵权，不合规会被拒 |
| 冷色主导（蓝 / 紫 / 灰底） | 违背暖色品牌调性（呼应音频圣经 C/G 五声音阶暖调） |
| 强投影 / 外发光溢出到出血区 | 被圆角切掉后留下脏边 |
| 真实截图直接当图标 | 双盘 8×4 格在 100px 下完全无法辨认 |
| 深色描边包裹整个图标 | 与"轻盈、少描边"风格支柱（美术圣经 §1）相悖 |

## 6. 交付前自检清单（Checklist）

落地后请逐条核对：

- [ ] 尺寸正好 512×512，PNG-24，sRGB
- [ ] **缩到 96×96 后**，仍能一眼看出"两块方块 + 数字"（把图缩小眯眼看，这是最有效的检验）
- [ ] **灰度化后**，前块与后块仍有明显明度差（美术圣经 §8.1 色弱友好要求）
- [ ] 数字与方块底色对比度 ≥ 4.5:1（`#4A2A0E` on `#FFC97B` / `#FFA95E` 均达标）
- [ ] 关键内容全部在内圈 416×416 安全区内
- [ ] 四角满铺背景色，无透明缺口、无自带圆角
- [ ] 无任何促销文案 / 第三方 Logo
- [ ] 文件体积 ≤ 200KB
- [ ] 在**浅色卡片**和**深色卡片**两种背景上分别预览，均不"融进去"

## 8. 封面设计规范（v2.0 · 平台必填）

### 8.1 设计系统（三图统一）

三张封面必须**视觉风格一致**——用户在方形和横版之间要能认出是同一款游戏。

| 元素 | 规格 | 色值来源 |
| --- | --- | --- |
| 背景 | 垂直渐变：暖奶油白 → 蜜桃粉 | `#FFF9EF` → `#FFE6D2`（art-bible §2.2 方案 A） |
| 中心柔光 | 径向柔光，让主视觉从背景浮起 | 白色 @70% alpha |
| 主视觉 | **两块倾斜的 4×4 棋盘**（双盘 = 核心差异化卖点） | 棋盘外框 `#E7D0A8`，空格 `#F3E7D3`，方块色板见 art-bible §2.1 |
| 标题 | **「Double 2048」**（唯一允许出现的文字） | Double = 深棕 `#4A2A0E` + 白描边；2048 = 金色 `#FFB014` + 深棕粗描边 |
| 标题字体 | **Arial Rounded MT Bold**（圆润卡通，非默认字体） | Windows: `ARLRDBD.TTF`；备选: arialbd / ariblk |
| 点缀 | 金色四角星芒 | `#FFB014` |

### 8.2 三张封面的布局差异

| 封面 | 比例 | 标题位置 | 棋盘布局 | 倾斜角度 |
| --- | --- | --- | --- | --- |
| Landscape | 16:9 (1920×1080) | 左侧居中 | 双盘**左右并排**（呼应横屏实际玩法） | 左盘 +6° / 右盘 -6° |
| Portrait | 2:3 (800×1200) | 顶部居中 | 双盘**上下堆叠**（呼应竖屏实际玩法） | 上盘 +5° / 下盘 -5° |
| Square | 1:1 (800×800) | 顶部居中 | 双盘**左右并排**（紧凑版） | 左盘 +6° / 右盘 -6° |

> **为什么棋盘要倾斜？** 正对观众的平铺棋盘在封面里显得呆板、像截图。
> 微倾 5–6° 让画面有"动态感"和"设计感"，符合官方「鼓励原创设计封面」的要求。

### 8.3 棋盘内容策略

两块棋盘展示的是**真实中局状态**（非空盘开局），包含：
- **左/上盘 (GRID_A)**：有 512 金色方块（黄金段位），体现进度
- **右/下盘 (GRID_B)**：有 1024 深金黄方块（更高段位），体现挑战
- 两盘方块分布**刻意不同**（同一操作不同结果 = 策略张力）
- 包含 32/64 红橘系方块（视觉重量锚点）

具体格子内容见 `tools/gen_covers.py` 的 `GRID_A` / `GRID_B` 常量。

### 8.4 合规检查（官方硬性禁止项）

| ✗ 禁止 | 本设计是否合规 | 说明 |
| --- | --- | --- |
| 加边框 | ✅ 无边框 | — |
| 除标题外写文字 | ✅ 仅 "Double 2048" | 方块数字属于游戏内容，非 UI 文字 |
| 放图标或商店 logo | ✅ 无 | — |
| 用无版权素材 | ✅ 全部程序化绘制 | PIL 渲染，无外部图片 |
| 模糊/像素化 | ✅ 2x–2.7x 超采样抗锯齿 | — |
| 直接用游戏截图当封面 | ✅ **原创设计稿** | 棋盘是按美术圣经色板程序化绘制的"设计插图"，不是引擎截图 |

## 9. 预览视频首帧规范（v2.0 · 平台必填）

### 9.1 规格要求

| 项 | 要求 | 产出文件 |
| --- | --- | --- |
| 横版首帧 | 1920×1080 (16:9)，与横版封面**像素级一致** | `video-firstframe-landscape-1920x1080.png` |
| 竖版首帧 | 1080×1620 (2:3 @1080p)，与竖版封面同构图 | `video-firstframe-portrait-1080x1620.png` |
| 格式 | PNG（作为视频第一帧嵌入） | — |
| 内容 | 与对应比例封面**无缝衔接**（玩家悬停看到封面 → 点击播放 → 第一帧就是封面） | — |

### 9.2 视频制作建议（供用户/剪辑参考）

> **注意：本脚本只产出静态首帧。完整 MP4 视频需从浏览器录制游戏实况后剪辑。**
> 以下为分镜建议：

| 时间 | 画面 | 时长 |
| --- | --- | --- |
| 0–3s | **静态封面帧**（即本节产出的首帧） | 3s（品牌识别） |
| 3–10s | **双盘同步滑动核心爽点**：一次方向键操作 → 两盘同时滑动 → 合并弹跳动画 | ~7s |
| 10–15s | **数字成长快剪**：快速闪过 16→64→256→512→1024 的合并过程 | ~5s |
| 15–18s | **差异化机制展示**：冻结遮罩出现（一盘锁定）或退役 DONE 出现 | ~3s |
| 18–20s | **回到封面帧淡出**或定格在 2048 达成瞬间 | ~2s |

**视频硬性禁止项**：
- [ ] 有声（必须静音）
- [ ] 黑屏/logo 转场
- [ ] 上下黑边（letterbox）
- [ ] 鼠标指针可见
- [ ] "Play Now" / "Play now" 类推广文字
- [ ] 社交图标
- [ ] 自行加速（平台会自动略微加速）
- [ ] 超过 20 秒

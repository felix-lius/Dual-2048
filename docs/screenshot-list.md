## 0. 重要前置说明（拍摄前必读）

### ⚠️ 本作**没有主菜单画面**

`src/main.js` 第 2 行注释明确：

```js
// ITER-V6-REDO-001 ③：去首页 —— 只保留 GameScene 直接启动（默认硬核，游戏内可切模式/语言）
scene: [GameScene],
```

## 1. 拍摄通用规范

| 项 | 要求 |
| --- | --- |
| 横屏尺寸 | **1920×1080**（16:9），最低 1280×720 |
| 竖屏尺寸 | **1080×1920**（9:16），最低 720×1280 |
| 格式 | PNG（无损）或高质量 JPG（质量 ≥ 90） |
| 语言 | **英文版为主**（平台主要受众）；中文版另存一套备用 |
| 浏览器 | 隐藏地址栏 / 书签栏；用 F11 全屏或 DevTools 设备模式精确出图 |
| 禁止出现 | 报错横幅（`__err_banner__` 红条）、DevTools 边框、鼠标光标、调试文字 |
| 分数状态 | **不要用刚开局的 0 分**去拍对局图 —— 先玩到有 128/256 大数字再截，画面更有说服力 |
| 命名 | `shot-L1-first-screen.png`（L=横屏）/ `shot-P1-first-screen.png`（P=竖屏） |

### 出图方法建议

```bash
# 用 DevTools 设备模式设定精确分辨率，或直接 resize 浏览器窗口
# Chrome DevTools → Ctrl+Shift+M → 自定义尺寸 1920×1080 / 1080×1920
# 截图：Ctrl+Shift+P → "Capture screenshot"
```

## 2. 横屏截图清单（3 张，优先级排序）

### 📸 L1 · 双盘激战中（**封面图，最重要**）

| 项 | 内容 |
| --- | --- |
| 画面 | 横屏左右双盘并排，两盘都有较满的方块，**至少一盘出现 256 或 512 的金色方块** |
| 状态 | 硬核模式；总分 3000+；撤销/冻结还有剩余次数 |
| 必须可见 | 左盘分 / 总分 / 右盘分、两块完整棋盘、底部 3 按钮控制条 |
| **卖点** | **「一次滑动，同时操控两个棋盘」——这是全作最核心的差异化，必须是第一张** |
| 拍摄要点 | 两盘方块分布**刻意不同**（体现"同一操作、不同结果"的策略张力）；金色高数值方块尽量靠画面中部，视线第一落点 |

### 📸 L2 · 失败结算 + 看广告续命

| 项 | 内容 |
| --- | --- |
| 画面 | 深海军蓝 78% 全屏遮罩，白色大字「Game Over」+ 副标题，下方**两个按钮** |
| 必须可见 | **「Watch ad: undo 5 moves, keep playing」（`rewindAdBtn`，360×56）** + 「Play Again」（200×60） |
| **卖点** | **「输了不用重来 —— 看个广告直接回退 5 步」**，这是留存与变现的关键机制，也是对休闲玩家的强吸引力 |
| 拍摄要点 | 遮罩半透明，**背后的双盘要隐约可见**（证明"进度还在，可以救回来"）；分数要高（体现"值得救"） |

### 📸 L3 · 冻结机制生效中

| 项 | 内容 |
| --- | --- |
| 画面 | 一盘正常，**另一盘盖着深蓝 55% 冻结遮罩 + 锁形图标 + 剩余步数** |
| **卖点** | **「策略道具：冻结一盘，专心救另一盘」**——证明这不是无脑双盘，而是有解法的策略游戏 |
| 拍摄要点 | 被冻结盘选**局面危险**的那一盘（快满了），对比才有故事感；剩余步数显示 2 或 3（正在倒数中） |

> 备选（若 L3 不好拍）：**休闲模式退役 DONE** —— 一盘盖青绿 60% 遮罩 +「DONE 达标」，卖点为「休闲模式：达标即退役，压力更小」。

## 3. 竖屏截图清单（3 张）

### 📱 P1 · 竖屏双盘上下堆叠（**竖屏封面**）

| 项 | 内容 |
| --- | --- |
| 画面 | 上下两盘堆叠，HUD 在顶（含「上盘/下盘」caption），控制条在底 |
| **卖点** | **「手机竖屏单手可玩，双盘完整同屏」**——向移动端用户证明适配良好，无需横屏 |
| 拍摄要点 | 两盘都要**完整不裁切**；有中高数值方块；这是移动流量的第一印象图 |

### 📱 P2 · 教程覆盖层（玩法说明）

| 项 | 内容 |
| --- | --- |
| 画面 | 点 `?` 后弹出的覆盖层：标题「How to Play」+ **4 条编号规则** + 「Got it」按钮 |
| 真实文案 | 1. 同一组方向键/滑动同时驱动两块棋盘 2. 任一盘先达 2048 即获胜 3. 某盘死局则判负 4. 善用撤销与冻结 |
| **卖点** | **「30 秒学会，规则极简」**——降低点击前的理解门槛，直接回答"这游戏怎么玩" |
| 拍摄要点 | 用**英文版**拍；背后棋盘要有内容（不要空盘） |

### 📱 P3 · 高分时刻 / 2048 达成

| 项 | 内容 |
| --- | --- |
| 画面 | 出现 **2048 王者金方块（带金色辉光 + 星芒角标）**，或胜利遮罩「You Win!」 |
| **卖点** | **「冲击 2048 的成就感」**——给玩家一个明确的目标画面，激发挑战欲 |
| 拍摄要点 | 金色辉光要拍在**脉冲最亮的一帧**；若难以刷到 2048，退而求其次拍 512/1024 满盘高分局 |

## 4. 拍摄顺序与发布排序建议

### 建议发布展示顺序

```
1. L1 双盘激战    ← 核心玩法，第一眼
2. L2 广告续命    ← 差异化机制 + 降低挫败感
3. P1 竖屏堆叠    ← 移动端适配证明
4. L3 冻结机制    ← 策略深度
5. P2 教程覆盖层  ← 打消"看不懂"顾虑
6. P3 2048 达成   ← 目标感收尾
```

### 高效拍摄流程

1. **先玩一局到中后期**（有 256+ 方块、分数 3000+），此时可连拍 L1 / L3。
2. 切竖屏窗口，同一局继续 → 拍 P1。
3. 点 `?` → 拍 P2。
4. 故意走到死局 → 拍 L2（结算含广告按钮）。
5. P3 需要单独刷分，可用休闲模式更易达成。
